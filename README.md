# 工业洗筐标签黏附变量筛选

项目短名 `yangfan-crate-label`。视觉采用工业黄和炭黑、测点档案。

澄湾周转器具再生中心质控组。澄湾为冷链仓配客户回收和清洗可循环塑料筐。两条班次合计每天约 1800 筐，4 名质控员从 PLC 与扫码台账拼接关键读数，逐批对照洗后标签留存，再把测点取舍交给设备组。当前试点优先分配三个采集通道。

导入每筐一行的洗筐 CSV，包含筐次编号、洗筐日期、批次、洗后目检脱落标记和六个候选测点的读数。脱落为 1，留存为 0。批次标记跨日时沿用原编号。 质控组获取测点互信息、相关替代关系和独立留出的模型表现。设备组按测点编号、位置和采集建议决定试装、复用扫码记录或暂缓采购。

- PLC 导出与扫码记录各用一套编号，质控员每班手工按筐次对齐。
- 同一个压力波动同时出现在泵电流和总管压力里，人工看排名容易重复采购。
- 同批周转筐分到训练和复核后，会把同一批工况当成独立验证。

## 六个业务模块

1. 洗筐质控总览
2. 筐次日志台账
3. 测点筛选配置
4. 测点排序明细
5. 留出试点复核
6. 试点清单分发

## 工作剧本

1. 08:10，组长盘点三路试点采集通道，确认 PT-21、CT-21 和末漂、烘干、扫码站共六个候选测点。
2. 08:25，质控员导入 chengwan_crate_wash_20261117-24.csv，核对 CW-1117-A 到 CW-1124-B 共 16 批、256 条。
3. 08:45，锁定 11 月 23 日为留出首日，核对训练 192 条、留出 64 条，再按 4 个目标分位箱、0.90 相关阈值和三路预算执行筛选。
4. 09:15，在测点明细对照 PT-21 与 CT-21 的互信息及冗余关系，同时检查留出混淆计数和多数类基线。
5. 10:20，质控长在复核页确认拟保留测点、传感器安装位置和替代关系，按独立留出表现决定能否批准试点。
6. 14:00，导出本次测点试点清单及留出验证成绩，发送给循环筐设备组安排下一班试装。

## 算法与复核

先锁定留出首日及其后批次，隔离这些批次较早的记录。训练集按分位点离散，合并重复边界，按经验互信息 Σ p(x,y)log₂[p(x,y)/(p(x)p(y))] 排序。从高分开始按训练集绝对 Pearson 相关系数去冗余并执行测点预算。以选出的训练分箱和拉普拉斯平滑朴素贝叶斯预测留出筐次，以训练多数类作基线比较平衡准确率。演示日志固定种子 20261125。

记录号重复、日期或测点读数无效、分区批次或样本量不足、任一区间缺少留存或脱落实例时提示修正。无入选测点或留出平衡准确率未高于基线时，报告保留结果并锁住发布。 复核问题为「哪些现有或候选测点应进入下一班试点，哪些由于冗余、预算或留出表现需暂缓？」。每次分析绑定数据版本和参数，原始数据按规范化内容的 SHA-256 去重。日程针对已复核的固定结果版本，每日模式按初次投递时间每 24 小时重复。停机期间错过多次时只补一份到站内收件箱，下一次回到原时间点。

| 字段 | 含义 | 类型 |
|---|---|---|
| `cycle_id` | 洗筐记录号 | str |
| `batch_id` | 洗筐批次 | str |
| `wash_date` | 洗筐日期（YYYY-MM-DD） | str |
| `detached` | 洗后标签脱落（1=脱落，0=留存） | int |
| `spray_pressure_bar` | PT-21 喷淋压力（bar） | float |
| `pump_current_a` | CT-21 喷淋泵电流（A） | float |
| `rinse_temp_c` | TT-32 末漂温度（°C） | float |
| `dryer_dewpoint_c` | DT-41 烘干露点（°C） | float |
| `label_dwell_min` | SC-11 贴标静置（min） | float |
| `conductivity_ms_cm` | EC-31 末漂电导率（mS/cm） | float |

## 启动

```sh
[ -f .env ] || cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

- Web 界面 `http://127.0.0.1:18372`
- API 文档 `http://127.0.0.1:19372/docs`
- 数据库端口 `17872`

| 账号 | 演示密码 | 工作权限 |
|---|---|---|
| analyst | analyst-demo-24 | 导入 CSV、运行分析、导出工作稿 |
| reviewer | reviewer-demo-24 | 复核、设置和停止投递、导出 |
| viewer | viewer-demo-24 | 浏览结果、导出已批准的报告、查收投递 |

原生 HTML/CSS/JavaScript 前端与 Nginx、FastAPI、Python worker、PostgreSQL 16 和 Redis 组成五服务 Compose。`backend/src/services/domain.py` 存放业务算法，`domain.json` 定义字段与验收口径，`frontend/src/pages` 为业务页面。更新任一侧源文件后，用 `docker compose up -d --build` 重建对应镜像。`backend/src/constants/enums.py` 和 `frontend/src/constants/enums.js` 定义角色及运行状态。`.env` 支持前端、API、数据库端口、演示 seed 开关和 JWT 密钥。首次部署到非演示环境时更换演示身份及 JWT/数据库凭据。

`docker compose down` 停止服务并保留数据卷。现场数据和演示结果可以在各自版本中并存。
